## 本次修复详情

### P0-1: 明文密码存储

**问题**：`UserInfo` 接口包含 `password?: string` 字段，`useAuth.ts` 中有本地密码比较逻辑，注册页面将密码写入 UserInfo 对象。

**修复**：
- 从 `UserInfo` 接口移除 `password` 字段
- 删除遗留的 `src/hooks/useAuth.ts`（无任何引用，仍做本地密码比较）
- `register/index.tsx`：创建 UserInfo 时不包含 password
- `change-password/index.tsx`：`storage.updatePassword(user.username)` 只传用户名
- `reset-password/index.tsx`：同上
- `storage.ts`：`updatePassword` 签名改为 `(username: string): boolean`，内部仍 delete password 兼容旧数据

### P0-3: 调试模式对用户可见

**问题**：Profile 页 5 点击"Miao"标题可进入 admin-settings，生产环境也可触发。

**修复**：
- `profile/index.tsx`：`handleAdminTap` 开头添加 `if (process.env.NODE_ENV !== 'development') return;`
- 生产构建时此代码会被 tree-shaking 移除

### P0-5: httpAdapter RequestResult 接口语法错误

**问题**：`RequestResult` 接口第一行属性名缺失，为 `   any;` 而非 `   any;`。

**修复**：
- 修正为 `   any;`

### P2-2: 猫咪播放器"喜欢"按钮无效

**问题**：`cat-player/index.tsx` 的 liked 状态仅用 `useState(false)`，页面离开后重置。

**修复**：
- `storage.ts` 新增 `isCatLiked(catId)` / `setCatLiked(catId, liked)` 方法，按猫咪 ID 持久化
- `cat-player/index.tsx`：初始值从 storage 读取，点击时同步写入 storage

### P2-6: QR 码生成器限制

**问题**：`qrCanvas.ts` 仅支持 QR Version 1-6（最大 136 字节），长 URL 会报错。

**修复**：
- 扩展 `QR_VERSIONS` 表至 Version 10（最大 274 字节）
- `selectVersion`：根据 version 动态计算 charCountBits（≤9 用 8 位，≥10 用 16 位）
- `encodeData`：char count 编码位数跟随 version 调整
- 错误提示更新为 "最大支持274字节"

### P3-5: 外部头像 API 依赖

**问题**：profile、edit-profile、create-companion、mockFriendService 仍使用 `api.dicebear.com` 作为降级头像。

**修复**：
- 新建 `src/utils/constants.ts`，导出 `DEFAULT_AVATAR = require('../assets/logo.png')`
- `profile/index.tsx`：替换 dicebear URL 为 `DEFAULT_AVATAR`
- `edit-profile/index.tsx`：同上
- `create-companion/index.tsx`：`onError` 降级改为 `DEFAULT_AVATAR`
- `mockFriendService.ts`：所有 avatar 字段改为空字符串

### P3-7: Login 页重复代码

**问题**：`handleLogin`、`handleWechatLogin`、`handlePhoneLogin` 三处协议检查代码重复（~10 行 × 3）。

**修复**：
- 提取 `checkAgreement(isAgreed, onDeny): boolean` 辅助函数
- 三处调用均替换为单行：`if (!checkAgreement(isAgreed, () => { ... })) return;`
