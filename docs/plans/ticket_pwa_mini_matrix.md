# 差异矩阵分析

## Problem Definition

需要基于已完成的跨工程扫描，把 PWA 与小程序的差异从文件级线索转化为可决策的功能/业务逻辑矩阵，明确哪些差异必须同步、哪些可以保持平台差异、哪些需要先补后端或验证环境。

## Proposed Solution

按照业务域拆分差异：路由页面、猫咪创建与 AI 生成、首页互动状态机、视频持久化与播放、积分兑换、账号认证、好友/日记/评论/通知、后台管理、内容安全、平台能力。每项给出当前状态、影响、同步可行性、推荐优先级。

## Acceptance Criteria

- 输出能直接回答“最近 PWA 更新是否已同步到小程序”。
- 标出至少 P0/P1/P2 三层同步优先级。
- 区分“业务必须一致”和“平台实现可不同”。
- 标出需要后端支持、微信能力支持或真机验证的项。

## Verification Plan

- 使用扫描结果和关键源码证据交叉验证。
- 对近期 PWA 提交涉及的核心文件逐项映射到小程序对应文件。
- 不把页面命名一致误判为业务逻辑一致。

## Risks

- 部分 PWA 服务端能力如果已部署到生产，小程序可直接受益；如果未部署，则仍是后端差异。
- 小程序当前工作区存在未提交修复，本矩阵默认按“当前工作区”评估，不按远端 `master` 原始状态评估。
