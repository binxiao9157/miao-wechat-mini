# 扫描两端工程

## Problem Definition

需要重新检查 `Miao` PWA 工程与 `miao-wechat-mini` 小程序工程的最新差异，识别页面功能、服务层、数据模型、接口协议、存储同步、鉴权登录、内容生成、社交关系、通知积分和调试能力的对齐状态。

## Proposed Solution

从两个工程的文件结构、路由配置、依赖配置、服务目录、页面目录、接口调用和最近 Git 变更入手，建立可核查的功能清单和业务逻辑清单。重点判断 PWA 最近更新是否已同步到小程序，以及哪些差异属于平台适配差异、可同步差异或不建议同步差异。

## Acceptance Criteria

- 明确确认 `Miao` 是否为 PWA 主工程，并记录其技术栈和入口结构。
- 列出 PWA 与小程序各自的页面、服务、核心业务模块。
- 识别 PWA 最近更新的文件和业务区域。
- 形成后续差异矩阵分析可直接使用的证据清单。

## Verification Plan

- 使用 `git status`、`git log`、`rg --files`、`find`、`package.json`、路由配置和服务目录扫描两个工程。
- 对页面和服务文件进行模块归类，而不是只看文件名。
- 对接口路径、存储 key、核心业务状态流进行抽样核对。

## Risks

- PWA 最近更新如果未提交，只能基于当前工作区状态判断。
- 两端技术栈差异较大，某些能力不能逐字复制，只能做业务语义对齐。
- 当前小程序工程有未提交稳定性修复，分析时需要区分“已有改动”和“尚未提交状态”。
