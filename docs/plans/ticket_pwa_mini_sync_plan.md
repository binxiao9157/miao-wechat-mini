# PWA 与小程序同步方案输出

## Problem Definition

需要把 PWA 与小程序差异矩阵转化为可执行的同步方案，明确哪些能力应立即同步、哪些保持平台分叉、哪些需要后端或真机验证先行，避免在没有边界的情况下直接迁移 PWA 代码导致微信端体验或稳定性回退。

## Proposed Solution

输出一份分阶段开发计划，按 P0/P1/P2/P3 拆分后端接口、数据模型、生成流程、首页播放器、内容安全、积分策略、后台管理和验证发布。方案采用“业务语义对齐、平台实现分叉”的原则：两端共享动作模型、prompt、接口协议和数据字段，小程序保留 Taro/微信端实现方式。

## Acceptance Criteria

- 明确回答 Miao 是否是 PWA 工程，以及两端是否适合直接代码同步。
- 给出 PWA 最近更新需要同步到小程序的完整范围。
- 输出按优先级拆分的实施步骤，每一步包含目标、涉及模块、风险和验证方式。
- 明确不可直接同步或需产品决策的项，如积分自动补足、后台管理入口、PWA 离线能力。
- 标出上架前必须补齐的后端和真机验证项。

## Verification Plan

- 方案必须可回溯到 `result_pwa_mini_matrix.md` 的差异结论。
- 检查每个高风险差异是否都有对应实施或保留策略。
- 检查计划是否避免把浏览器 `video/canvas`、Service Worker、React Router state 等 PWA 实现直接套入小程序。
- 检查验证策略是否覆盖 `npm test`、`npm run build:weapp`、`npm run build:h5`、真机视频播放/上传/登录/隐私授权。

## Risks

- 生产服务端是否已经部署 PWA 最新 AI 和持久化能力，需要接口实测确认。
- 小程序本地提取视频尾帧能力不确定，推荐优先服务端提帧或生成任务返回尾帧。
- 四段式视频状态机属于核心体验迁移，必须灰度并保留旧动作 key 兼容。
