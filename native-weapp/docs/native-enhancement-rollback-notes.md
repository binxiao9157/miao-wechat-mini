# 原生增强能力临时收敛记录

> 记录时间：2026-05-10  
> 当前目标：原生小程序先以旧版非原生微信小程序为视觉与交互基准完成对齐。  
> 说明：以下项目并不一定是功能倒退，当前处理方式主要服务于“像素级/结构级对齐”。后续可根据微信开发者工具和真机实测结果，评估是否以不破坏旧版主视觉的方式恢复原生增强能力。

## 1. 首页工具栏与动作栏

- 当前处理：隐藏原生迁移期新增的顶部工具栏和底部动作栏。
- 涉及能力：顶部“切换 / 历史 / 我的”，底部“蹭蹭 / 摸头 / 踩奶 / 逗猫 / 补齐”等显式入口。
- 收敛原因：旧版首页是沉浸式视频页，没有这些显式按钮；新增控件会明显改变首页主视觉和交互密度。
- 后续恢复建议：如果真机验证认为显式动作入口更利于发现和使用，可考虑恢复为轻量浮层、长按菜单、右下角折叠按钮，或仅在首次引导/无手势提示时显示。

## 2. 空猫页与猫咪启动页

- 当前处理：对齐旧版返回按钮、文案、插图装饰和按钮样式。
- 涉及能力：原生迁移期曾有更直接的创建/上传引导文案和部分新样式。
- 收敛原因：旧版页面在标题、卡片文案、按钮尺寸、插图层次和返回按钮形态上已有固定基准；原生版此前视觉语言偏移较大。
- 后续恢复建议：如实测发现旧版文案不够清晰，可保留旧版布局和尺寸，只在副文案或卡片说明中小幅增强表达。

## 3. 陪伴里程碑页

- 当前处理：从原生“统计英雄页”改回旧版“天数卡片 + 月历 + 温馨寄语”。
- 原生增强内容：大英雄卡片、日记数、视频数、里程碑清单，如“陪伴 7 天 / 30 天 / 记录 10 篇日记”。
- 收敛原因：原生统计页信息密度更高，但与旧版页面结构差异过大；旧版基准强调陪伴天数、月历爪印和情感寄语。
- 后续恢复建议：统计能力有保留价值，可考虑放到月历下方的次级折叠区，或作为“更多里程碑”入口，而不是替代旧版主结构。

## 4. 反馈页

- 当前处理：恢复旧版问卷文案、存储 key、问题类型标签、500 字限制、“发送反馈”文案，以及成功后自动返回。
- 原生增强内容：原生版使用了独立 storage key、更长反馈字数、提交后停留成功页、部分错误 toast。
- 收敛原因：storage key 不一致会影响旧用户状态延续；文案、字数和提交行为与旧版不一致会造成体验偏差。
- 后续恢复建议：storage key 建议保持旧版兼容；提交后停留成功页、错误提示强化、字数上限提升可以根据实测反馈再决定是否恢复。

## 5. 好友二维码页

- 当前处理：隐藏原生额外的“复制邀请码 / 复制邀请链接 / 重新生成”和二维码预览入口，保留旧版“保存图片 / 分享给好友”的简洁动作区。
- 原生增强内容：复制邀请码、复制邀请链接、重新生成邀请码、点击二维码全屏预览。
- 收敛原因：旧版二维码页动作区更轻，额外按钮会改变页面底部布局和操作层级。
- 后续恢复建议：这些增强能力有实用价值，可考虑移入右上角更多菜单、长按二维码菜单、或“更多操作”折叠面板中恢复。

## 6. 扫码页副标题与页头

- 当前处理：去掉原生额外副标题 `SCAN FRIEND QR`，并收紧页头样式。
- 原生增强内容：标题下方英文副标题，以及更强的原生页头视觉。
- 收敛原因：旧版扫码页只有主标题，副标题会导致页头高度和视觉重心偏移。
- 后续恢复建议：如需要品牌感或英文辅助信息，可放在扫码框下方说明区，而不是页头主结构中。

## 7. 日记页同步状态与媒体修复面板

- 当前处理：在日记卡片主视觉中隐藏原生迁移期新增的 `未同步` 标记和同步失败修复面板。
- 原生增强内容：日记同步失败时展示 `sync-badge`、错误说明、`重试同步`、`重新选择媒体` 等操作；媒体加载失败时有本地 fallback 与修复入口。
- 收敛原因：旧版 `DiaryCard` 没有同步状态 UI，卡片结构是头像、正文、媒体、图标互动行、评论区；同步面板会改变卡片高度、信息层级和视觉密度。
- 后续恢复建议：同步修复能力有 QA 和容错价值，建议后续恢复到“更多操作”、长按卡片菜单、或仅在开发/调试开关下显示，避免常态打断旧版卡片布局。

## 8. Miao/Profile 页功能菜单入口

- 当前处理：Miao/Profile 主菜单恢复为旧版“账户设置”六项：个人资料设置、通知设置、意见反馈、清除缓存、退出登录、注销账户；同时保留顶部扫码/消息按钮、伙伴卡片、统计卡片等旧版主入口。
- 原生增强内容：原生迁移期曾在 Profile 主菜单中额外展示切换猫咪、陪伴里程碑、生成新猫咪、时光信、邀请好友、消息中心、隐私设置、隐私政策、服务条款等入口。
- 收敛原因：这些入口虽然提升了功能发现度，但会把旧版账号设置列表改造成“全功能中心”，导致首屏信息结构、卡片数量、滚动高度和底部 TabBar 遮挡状态都与旧版明显不一致。
- 后续恢复建议：若真机 QA 认为这些入口仍需保留，建议迁移到“更多功能”折叠区、二级功能页、右上角更多菜单，或按旧版入口关系分散到伙伴卡片、消息按钮、底部导航和各功能页面内，避免继续改变 Profile 主视觉。

## 后续评估原则

1. 先完成旧版主视觉、主路径和关键交互对齐。
2. 真机 QA 后，将上述增强点按“高价值 / 可选 / 不恢复”分类。
3. 恢复增强能力时，优先采用折叠、更多菜单、长按、轻量浮层等方式，避免改变旧版首屏结构。
4. 对涉及用户数据连续性的项，例如 storage key、分享路径、邀请码逻辑，优先保持兼容，不做仅视觉层面的反复切换。
