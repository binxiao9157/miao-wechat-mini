# Taro 版本与 Native 原生小程序开发验收文档

> 生成时间：2026-05-10  
> 当前分支：`native-weapp-mvp`  
> 当前基线提交：`001fb15 Polish native miniapp visual alignment`  
> Taro 基准：`src/`，`src/pages/*`，`src/components/*`，`src/services/*`  
> Native 目标：`native-weapp/miniprogram/`  
> 验收目标：原生微信小程序在 UI、布局、颜色、字体、图标、交互、数据链路和整体业务功能上，对齐当前 Taro 微信小程序版本；确认为原生能力而临时收敛或后续恢复的点需可追踪。

---

## 1. 验收结论摘要

### 1.1 当前覆盖度

| 维度 | 当前结论 |
|---|---|
| 页面覆盖 | Taro 32 个页面，Native 32 个业务页面均已存在；Native 额外新增 `bootstrap` 启动页 |
| 设计令牌 | 核心色彩、圆角、阴影、文字色 token 已基本一致 |
| TabBar | 图标、尺寸、中心按钮、激活点、首页半透明态已接近 Taro；Native 已支持事件隐藏/显示 |
| 安全区 | Native 已新增 `utils/layout.js`，根据微信胶囊真实 `bottom` 动态计算页头避让 |
| 主业务链路 | 登录、注册、猫咪创建/上传、生成、首页播放、日记、信件、积分、个人中心、好友、通知、设置链路均有 Native 实现 |
| 数据服务 | Native 使用 `authService`、`dataStore`、`contentStore`、`socialStore`、`syncManager`，整体比 Taro 更接近服务端同步模型 |
| 当前风险 | 仍需通过微信开发者工具截图和真机 QA 对“像素级视觉一致性”和授权/媒体/分享等原生能力做最终确认 |

### 1.2 发布判断

当前 Native 版本可以进入系统 QA 阶段，但不建议直接视为最终可切换版本。原因不是主功能缺失，而是以下类型必须真机确认：

- 不同 iPhone 机型下，胶囊按钮、灵动岛、状态栏与页面 Header 是否持续不遮挡。
- 首页视频播放、相册保存、上传生成、扫码、分享、手机号登录等微信原生能力在真实权限环境下是否稳定。
- 低频页面仍需逐页截图确认：协议、隐私政策、管理页、扫码、加入好友、下载页、通知列表、隐私设置等。
- Taro 原有的部分“轻交互”能力在 Native 中采用了原生替代方案，需要产品确认是否接受。

## 2. 验收基准与范围

### 2.1 基准定义

本次验收以当前 Taro 微信小程序源码为视觉和业务基准：

- 页面源码：`src/pages/*/index.tsx`
- 页面样式：`src/pages/*/index.less`
- 全局样式：`src/app.less`
- 自定义底栏：`src/custom-tab-bar/*`
- 公共组件：`src/components/common/*`、`src/components/layout/*`
- 业务服务：`src/services/*`
- 工具适配：`src/utils/*`

Native 对照范围：

- 页面源码：`native-weapp/miniprogram/pages/*`
- 全局样式：`native-weapp/miniprogram/app.wxss`
- 原生底栏：`native-weapp/miniprogram/components/tab-bar/*`
- 业务服务：`native-weapp/miniprogram/services/*`
- 原生工具：`native-weapp/miniprogram/utils/*`
- 验收辅助文档：`native-weapp/docs/*`

### 2.2 不纳入“必须完全一致”的项

以下差异可接受，但必须明确记录：

- React/Taro 与原生小程序生命周期不同导致的代码结构差异。
- `Taro.showModal`、自定义弹窗、`wx.showModal` 的表现差异，只要关键文案、危险操作确认、成功/失败反馈完整即可。
- 原生微信小程序权限弹窗、分享面板、手机号授权面板无法做到 Taro 自定义 UI 的完全一致。
- Native 为稳定数据同步增加的 store、sync queue、任务恢复能力，只要不破坏 Taro 主视觉和主路径，可作为增强保留。
- 已写入 [native-enhancement-rollback-notes.md](./native-enhancement-rollback-notes.md) 的原生增强收敛项，按文档约定后续再评估恢复。

## 3. 全局 UI / 设计系统验收

### 3.1 颜色

| Token | 值 | 验收要求 | 当前静态结论 |
|---|---|---|---|
| `--primary` | `#E89F71` | 主按钮、积分强调、Tab 激活、提示色一致 | 已对齐 |
| `--primary-strong` | `#FF9D76` | 徽标、强调按钮、头像编辑按钮一致 | 已对齐 |
| `--background` | `#FFF9F5` | 页面暖白背景一致 | 已对齐 |
| `--surface` | `#FFFFFF` | 卡片背景一致 | 已对齐 |
| `--surface-container` | `#FEF6F0` | 输入框、浅按钮、积分不足按钮一致 | 已对齐 |
| `--on-primary-container` | `#633E1D` | 大标题、主文字一致 | 已对齐 |
| `--on-surface-variant` | `#8E8E8E` | 英文副标题、次级说明一致 | 已对齐 |
| `--color-danger` | `#FF4D4F` | 删除、注销、错误提示一致 | 已对齐 |

验收标准：

- 页面截图中不得出现明显偏冷灰、偏蓝紫、过暗棕色的漂移。
- 同一业务语义的颜色必须一致，例如删除/注销统一危险红，积分强调统一暖橙。
- 允许 Native 为微信系统弹窗保留系统色，但页面内自绘 UI 应按 token。

### 3.2 字体与字号

| 层级 | 推荐值 | 典型页面 | 验收要求 |
|---|---:|---|---|
| 主页面标题 | `60rpx` / `900` | 日记、信件、积分、Miao | 同类主标题切换时不跳动 |
| 英文副标题 | `20rpx` / `700` | `DAILY MOMENTS`、`TIME CAPSULES` | 大写、字距和颜色统一 |
| 卡片标题 | `28-34rpx` / `800-900` | 兑换卡、设置项、菜单项 | 不截断、不溢出 |
| 正文 | `26-28rpx` | 日记正文、协议正文 | 行高舒适，可读性一致 |
| 辅助说明 | `22-24rpx` | 说明、时间、提示 | 不抢主内容 |
| TabBar 文本 | `20rpx` / `800` | 底部导航 | 激活文本、圆点位置一致 |

当前风险：

- 部分低频页面仍可能存在 Native 字重偏重的问题，需截图走查。
- 协议/隐私政策长文本需要检查行高、段落间距、列表缩进。

### 3.3 布局与安全区

| 项目 | 验收要求 | 当前实现 |
|---|---|---|
| 顶部胶囊避让 | Header 不与微信胶囊、灵动岛、状态栏遮挡 | Native 通过 `getHeaderSafeTop()` 动态读取胶囊底部 |
| 底部 TabBar 避让 | 页面底部内容不被 TabBar 和 home indicator 挡住 | 多页面使用 `calc(220rpx + env(safe-area-inset-bottom))` 或等效底部 padding |
| 页面滚动模型 | 日记、信件、积分、Miao 顶部区域应随页面滚动 | 关键页已改为 Header 在 scroll 内容内 |
| 宽度对齐 | 同一页面内大卡片、列表、按钮边缘需沿同一栅格 | Miao、积分近期已调整；低频页仍需截图确认 |
| 交互按钮尺寸 | 同类图标按钮 `96rpx` 容器、`48rpx` 图标优先 | 日记/信件加号已统一 |

验收设备：

- iPhone 15 Pro / 15 Pro Max 模拟器。
- iPhone 14 / 13 模拟器。
- iPhone SE 或小屏模拟器。
- 至少一台真实 iPhone。
- 至少一台 Android 微信真机。

## 4. 全局组件对齐验收

### 4.1 TabBar

| 项目 | Taro | Native | 验收标准 |
|---|---|---|---|
| 页面项 | 日志、时光、首页、积分、MIAO | 一致 | 5 项顺序完全一致 |
| 图标 | PNG 图标资源 | 同资源路径迁移到 `/assets/profile-icons` | 切页时图标尺寸不跳动 |
| 中心首页 | 圆形凸起 | 一致 | 圆心、阴影、激活态一致 |
| 首页态 | 半透明毛玻璃 | Native 已有 `backdrop-filter` 和 `-webkit-backdrop-filter` | 首页视频页底栏可读且不突兀 |
| 显隐 | `tabbar:hide/show` | Native 事件总线支持 | 弹窗、播放页、全屏页不被误挡 |
| 路由 | `Taro.switchTab` | `wx.switchTab`，失败降级 `redirectTo/reLaunch` | Tab 页面切换无白屏 |

### 4.2 Header / PageHeader

Taro 使用 `PageHeader`、`useNavSpace()` 和页面内大标题组合；Native 当前采取页面内联 Header + `utils/layout.js` 动态胶囊安全区。

验收标准：

- 所有有大标题页面，主标题不能顶到胶囊下方阴影。
- 日记、信件、积分、Miao 切换时 Header 垂直节奏一致。
- 返回按钮页面需检查返回按钮是否位于安全区内，且不遮挡标题。
- 对于有右上角操作按钮的页面，图标大小、按钮圆角、间距必须一致。

### 4.3 图标

| 图标类型 | 验收要求 |
|---|---|
| TabBar 图标 | 使用同一套 PNG；激活和未激活尺寸一致 |
| Header 图标 | `96rpx` 容器，`48rpx` 图标；不使用原生 `button` 默认样式污染 |
| 设置项图标 | 统一 `72-80rpx` 背景块；图标 `36-40rpx` |
| 反馈/通知/隐私图标 | 不再使用文字替代图标，需优先用资产 |
| 危险操作图标 | 删除/注销统一红色资产 |

## 6. 关键业务链路验收清单

### 6.1 认证与账号

- [ ] 未登录启动进入登录页。
- [ ] 密码登录成功后，自动进入首页或无猫页。
- [ ] 注册后进入后续昵称/首页链路。
- [ ] 微信一键登录在微信开发者工具和真机均可触发。
- [ ] 手机号快捷登录：未同意协议时拦截；用户拒绝授权时提示清晰；开发版 fallback 只在开发环境启用。
- [ ] 忘记密码完整跑通：发送验证码、重设密码、返回登录。
- [ ] 修改密码成功后，本地 token / 用户信息不丢失或按产品要求重新登录。
- [ ] 退出登录清理会话但不误删猫咪/日记核心缓存。
- [ ] 注销账户有二次确认，失败时行为符合产品预期。

### 6.2 猫咪生成与视频

- [ ] 无猫用户可进入猫咪启动页。
- [ ] 选择预设猫可创建伙伴。
- [ ] 上传猫咪照片可预览、压缩、提交生成。
- [ ] 生成进度页可轮询 AI 图片/视频任务。
- [ ] 生成失败时可重试或返回。
- [ ] 生成成功后猫咪出现在首页、历史页、切换页。
- [ ] 首页视频自动播放、循环、静音。
- [ ] 切换动作视频时不白屏，不错播。
- [ ] 视频保存相册权限被拒绝时，可跳转设置或给出明确提示。

### 6.3 日记与好友动态

- [ ] 发布纯文字日记。
- [ ] 发布图片日记。
- [ ] 发布视频日记，超过大小限制时提示。
- [ ] 删除自己的日记需要确认。
- [ ] 点赞自己的日记和好友日记分别按用户维度生效。
- [ ] 评论自己的日记和好友日记可同步。
- [ ] 长按评论可复制；有权限时可删除。
- [ ] 分享日记卡片可生成并携带正确路径。
- [ ] 好友动态同步成功；无好友时空态文案正确。
- [ ] 切换 `我的记录 / 好友动态` 时动画和内容不跳。

### 6.4 时光信

- [ ] 写信页选择收信猫、标题、内容、解锁天数。
- [ ] 未填写关键字段时提示。
- [ ] 保存后出现在列表。
- [ ] 未解锁信件点击显示等待提示。
- [ ] 已解锁信件可进入详情。
- [ ] 删除信件有二次确认。
- [ ] 调试快进开关仅在开发/调试场景生效。
- [ ] 信件同步后不重复、不丢失。

### 6.5 积分系统

- [ ] 每日登录积分一天只发一次。
- [ ] 在线时长积分达到条件后发放。
- [ ] 互动积分达到条件后发放。
- [ ] 积分明细正负值、时间、原因显示正确。
- [ ] 积分不足时兑换按钮不可误触发生成。
- [ ] 积分足够时进入兑换创建路径。
- [ ] 生成失败时积分扣退逻辑正确。
- [ ] 兑换卡 UI 与 Taro 对齐：图标居中、文案居中、按钮宽度和颜色一致。

### 6.6 好友邀请与扫码

- [ ] Profile 扫码入口可进入扫码流程或直接触发扫码，产品需确认最终交互。
- [ ] 扫码页可调用 `wx.scanCode`。
- [ ] 邀请二维码页可生成二维码。

## 7. 当前重点差异与验收风险

### 7.1 需要真机确认的 P0 风险

| 风险 | 说明 | 验收方式 |
|---|---|---|
| 顶部遮挡 | 微信胶囊、灵动岛、状态栏不同机型差异大 | 切 4 个模拟器 + 2 台真机截图 |
| 视频播放 | 模拟器与真机行为不同 | 真机测试自动播放、循环、切换、错误重试 |
| 相册保存权限 | 开发工具无法完全覆盖真实授权链 | 真机拒绝/允许权限各测一次 |
| 手机号登录 | 依赖微信开放能力和后端配置 | 真机或体验版验证 |
| 上传生成 | 大文件、弱网、后台切换可能暴露问题 | 弱网/中断/重进验证 |
| 分享路径 | 微信分享环境和普通路由不同 | 好友分享、群分享、时间线各测一次 |

### 7.2 需要产品确认的 P1 差异

| 差异 | 当前 Native 处理 | 产品决策 |
|---|---|---|
| 首页额外工具栏/动作栏 | 为对齐 Taro 已收敛或隐藏 | 是否后续以折叠方式恢复 |
| Profile 额外功能入口 | 主菜单恢复旧版 6 项 | 是否另建“更多功能”页 |
| 日记同步修复面板 | 主视觉隐藏 | 是否在长按菜单/更多操作中恢复 |
| 好友二维码复制/预览增强 | 当前按旧版简洁动作区优先 | 是否后续恢复 |
| 扫码允许相册 | Native 可支持更完整扫码能力 | 是否与 Taro `onlyFromCamera` 保持一致 |
| 时光信长按提前解锁 | Taro 有调试入口，Native 当前需确认 | 是否保留调试能力 |

### 7.3 需要开发复核的 P2 差异

- 长文本页：`privacy-policy`、`terms-of-service` 内容完整性需要逐段对照。
- 低频设置页：`admin-settings`、`privacy-settings`、`notification-list` 图标和列表密度需截图复核。
- 下载页、加入好友页、扫码页的空态/错误态截图需补齐。
- Native 若继续使用压缩 WXSS 片段，后续维护风险高，建议逐步格式化成可读样式块。

### 8.2 对齐标准

- 容器左右边距允许误差：`<= 4rpx`。
- 同类按钮高度允许误差：`<= 4rpx`。
- 字号必须完全一致，除非 Native 原生控件无法控制。
- 图标尺寸允许误差：`<= 2rpx`。
- 颜色应使用同 token，截图肉眼不得出现明显深浅漂移。
- 页面滚动到底部时，最后一项必须完整可见，不得被 TabBar 遮挡。
- 切换相邻 Tab 时，Header 高度、加号大小、TabBar 状态不得跳动。

## 10. Go / No-Go 标准

### 10.1 Go 标准

- [ ] 32 个业务页面均可打开，无 WXML/WXSS/JS 报错。
- [ ] 5 个底部 Tab 页面切换无白屏、无遮挡。
- [ ] 登录、注册、首页播放、猫咪生成、日记、信件、积分、Profile 主链路全部通过。
- [ ] 顶部胶囊避让在至少 4 个模拟机型和 2 台真机通过。
- [ ] 相册保存、扫码、分享、手机号授权、上传生成在真机通过。
- [ ] 所有 P0 问题关闭。
- [ ] P1 问题有明确产品决策或计划。

### 10.2 No-Go 条件

出现以下任一情况，不建议切换体验版：

- 登录后进入错误页面或会话恢复不稳定。
- 上传/生成链路会扣积分但无法恢复或退款。
- 首页视频在真机无法稳定播放。
- 任一核心 Tab 首屏被胶囊或 TabBar 明显遮挡。
- 清缓存、隐私清理、注销账户误删核心数据。
- 分享/邀请路径无法打开或无法添加好友。

## 12. 后续开发建议

1. 先完成截图矩阵，不再只靠代码静态判断 UI。
2. 将 `points/index.wxss` 等仍有压缩覆盖片段的页面逐步格式化，降低后续回归风险。
3. 将 Header 安全区策略沉淀成统一页面 mixin / helper 约定，避免每页单独漂移。
4. 对 `PageHeader`、`ConfirmModal`、`CatAvatar`、`DiaryCard` 这类 Taro 公共组件，在 Native 中抽象出等效组件，减少页面内联重复。
5. 对已收敛的原生增强能力，按照 [native-enhancement-rollback-notes.md](./native-enhancement-rollback-notes.md) 在 QA 后分级恢复。
6. 建立“每次 UI 修改后必须截 5 个 Tab 首屏 + 底部滚动图”的轻量回归流程。
